Local Bot Archive

Bot Profile Snapshots: when enabled, opening a chatbot profile stores the bot ID, name/title, creator, image, tags, Greeting, description and any definition/scenario/example fields, stats or other metadata that SpicyChat actually exposes to QoL. Meaningful profile changes are kept in profile history; stats-only observations stay separate where possible. QoL never unlocks or guesses private/hidden definition fields.

Successful Bot Status Center checks still update the local copy. The optional chat-open refresh uses a normal SpicyChat profile request only when the saved copy is older than this interval.

Public archive JSON: saved copies can be exported using only fields QoL actually captured. QoL never unlocks private/hidden definition fields.

Saved bot copies: successful profile checks can preserve the accessible name, description, greeting, personality/definition, scenario, example dialogues, tags, creator, visible stats and avatar URL in extension storage. A saved copy stays available here even if the live bot later disappears. Clearing status history does not clear these copies.

Update Watch: the first successful profile check becomes that bot's baseline. Later successful checks compare stable profile fields such as name, description, greeting, personality, scenario, tags, visibility, creator and avatar when SpicyChat exposes them. Missing fields are ignored instead of being treated as edits; use Accept update after reviewing a real change.

Duplicate / Reupload Finder: compares local names, avatars and captured profile text and labels matches as Exact, Likely or Possible. These are hints only and can have false positives; QoL never hides, blocks or deletes a bot because of a match.

Availability checks only mark clear results. Deleted/404 pages show as unavailable, private/restricted pages stay restricted, and timeouts or rate limits stay Unknown instead of being guessed as deleted.

How to set up DeepL
  1. Create or sign in to a DeepL account.
  2. Enable a DeepL API plan.
  3. Open the API Keys area in your DeepL account and copy your key.
  4. Paste it above, save it, then press Test DeepL.

The key is stored only in this browser's extension storage and is left out of QoL backups and diagnostics. When you translate, the selected message text is sent directly to DeepL, not to DragonScript.

Android/WebView: some app builds cannot show Chrome's optional host-permission prompt. QoL will still save the key and let Test DeepL check whether the app can reach DeepL. If that test still fails with a network/permission error, the Android wrapper needs DeepL host access.

Context Keeper

Quick setup: Light checks less often and keeps fewer details. Recommended uses the normal balanced defaults. Detailed checks more often and keeps more possible continuity.

Saved details do not use chat tokens by themselves. They stay local. Tokens are only used when you insert/send a Context Keeper recap; the recap size below has the biggest effect on how much context it uses.

Open Context Keeper from the chat three-dot menu or QoL panel. Automatic capture checks only small batches of new settled messages, favors durable facts over moment-to-moment narration, removes near-duplicates, and keeps manual/Memory details separate from the automatic cap.

Internal Day Tracker

Optional RP timeline helper suggested by Chibs. It keeps a local numbered story day and compact Storydate code so “yesterday”, “tomorrow”, “last night”, and older events have a stable reference point. Storydate uses day.phase: 35.3 means Day 35, evening.

Conservative mode only auto-applies strong transitions such as “the next morning”, “three days later”, an explicit “Day 35:” marker, or a numeric “Storydate 35.3”. Text after an explicit Day/Storydate marker becomes a compact timeline anchor, matching Chibs’ long-chat workflow. Assisted mode leaves weaker phrases such as “later that night” for you to accept or dismiss. Bare references such as “last night” or “tomorrow” do not advance the day by themselves. Existing chats start tracking from the current point unless you explicitly choose Scan loaded history in the tracker.

RP State Tracker

Keeps changing RP details separate from long-term memory, such as current location, inventory, worn clothing, injuries, stats, currency, party members, and active objectives. Suggestion credit: jumjam.

Conservative mode automatically reads clear state lines such as Inventory: flashlight, 2 medkits, Location: motel room 204, or State: HP=42/50; Gold=80. Assisted mode can also suggest simple changes such as picking up an item, putting on clothing, or arriving somewhere, but waits for you to approve them. State changes use the current Storydate when Internal Day Tracker is enabled.

The tracker stores state locally. If the bot needs to know the state, QoL sends a compact visible OOC state block with your message, which still uses some tokens. “When the state changes” avoids repeating the same block on every message.

Chatbot and Lorebook creation helpers, editor tools, moderation warnings, My Creations filters, and audits.

Bot & Lorebook backups

Chatbot backups & version history

When chatbot backup tools are enabled for the first time, automatic backups default to On. The default retention is 10 per bot and can be changed from 1–50. Manual checkpoints are kept separately and are never removed by this retention limit.

Bot Version History is separate from rotating safety revisions and manual checkpoints. A new version is recorded only when creator-controlled content actually changes: Name/Title, Greeting, Personality, Scenario, Example Dialogue, sorted Tags, Avatar, or a learned attached Lorebook association. Unchanged saves, message/like/rating changes, and visibility/review-state changes do not create a new version.

Visibility/review state is recorded separately for context. Compare shows field-level differences; Restore fills selected normal editor fields for review and never presses Save or publishes anything. Lorebook association is version metadata only and Restore does not automatically attach or detach a Lorebook.

With automatic saves turned off manually, nothing is saved until you click Save backup now. Export remains manual too.

Lorebook backups

Lorebook backups are separate from chatbot JSON. When automatic saves are off, the compact controls stay manual-only.

Backup tools remain opt-in. Once chatbot backup tools are enabled, automatic chatbot backups start On by default unless you turn them off. The Backup manager can still review or delete backups you already created after the editor controls are disabled.

Bot / profile export

Exports only fields the current public profile actually exposes. Available formats: JSON, Markdown, and a standalone HTML archive. QoL does not guess hidden Personality/Scenario/Example Dialogue fields on Greeting-only profiles.

Backup manager

Search your own chatbot backups, Bot Version History, manual checkpoints, rotating safety revisions, optional visited-profile snapshots, and Lorebook backups. Restore fills the normal SpicyChat editor for review and never presses Save for you; QoL creates a manual safety checkpoint before applying restored fields. Profile snapshots appear here when “Automatically save a Bot Profile Snapshot/history when I visit a chatbot profile” is enabled under Local Bot Archive.

SpicyChat QoL

Developed under DragonScript by DragonGRaf.

An independent quality-of-life project for SpicyChat focused on optional tools, local-first data, creator helpers, chat utilities, filtering, organization, and interface cleanup.

The extension uses normal SpicyChat pages/actions or information already available to the signed-in user. It does not unlock private character fields or publish creations automatically.
